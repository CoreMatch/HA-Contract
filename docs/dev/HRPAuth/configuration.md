# Configuration Structure

When the project is first started, a default configuration file `config.yaml` will be automatically generated in the root directory if it does not already exist.

> Detailed implementation: [`config/config.go`](../../config/config.go) · [`controllers/startup_controller.go`](../../controllers/startup_controller.go) · [`config/migrations.go`](../../config/migrations.go)

## Complete `config.yaml` Example

```yaml
version: "3"
site:
  name: "HRPAuth"
  implementation: "HRPAuth"
  version: "1.0.0"
server:
  port: ":8080"
  cors_origin: "*"
callback:
  url: "https://backend.auth.example.com/"
frontend:
  url: "https://auth.example.com/"
keygen:
  enable: 0
database:
  host: "localhost"
  db_name: "hrpauth"
  user: "root"
  password: ""
  charset: "utf8mb4"
verification_code:
  code_ttl: 600
  storage_dir: "./cache/verification_codes"
redis:
  host: "localhost"
  port: 6379
  password: ""
  db: 0
  prefix: "hrpauth_"
smtp:
  host: "smtp.example.com"
  port: 587
  username: ""
  password: ""
  encryption: "tls"
  from_email: "noreply@example.com"
  from_name: "HRPAuth"
manage:
  token: "<auto-generated on first startup>"
security:
  password_cost: 10              # bcrypt cost for HRPAuth user passwords
  rate_limit_max_attempts: 10    # Max login failure count
  rate_limit_window_sec: 600     # Login failure window (seconds)
  enable_captcha: true           # Enable graphical captcha (mandatory validation for /register)
  captcha_ttl: 300               # Captcha TTL (seconds), stored in Redis
yggdrasil:
  server:
    name: "My Server"
    implementation: "HRPAuth"
    version: "1.0.0"
    signature_public_key_path: "public_key.pem"
    signature_private_key_path: "private_key.pem"
    textures_storage: "./"
    links:
      homepage: ""
      register: ""
    skin_domains:
      - "example.com"
  security:
    token_expiry_days: 15        # accessToken TTL (days)
    session_expiry_seconds: 28800 # Refresh token/session TTL (seconds)
    max_texture_width: 1024      # Max texture width (px)
    max_texture_height: 1024     # Max texture height (px)
  feature_flags:
    non_email_login: false
    legacy_skin_api: false
    no_mojang_namespace: false
    enable_mojang_anti_features: false
    enable_profile_key: false
    username_check: true
    enable_ip_check: false
```

## Version Control and Auto-Migration

The top-level `version` field in the configuration file indicates the **schema version**. When the program starts, it automatically upgrades the configuration based on the version, using **chain-linked version-by-version migration** (each version has its own migration function, see [`config/migrations.go`](../../config/migrations.go)):

| Version | Changes |
|---------|---------|
| `1.0` | Initial YAML configuration (`memcache` captcha, no redis) |
| `2` | Added `redis`; renamed `memcache` to `verification_code` |
| `3` (Current) | Moved `security` fields (including captcha) from `yggdrasil.security` to the top-level `security`; added `manage.token`; default `redis.prefix` is `hrpauth_` |

Migration Behavior:

- **Automatic Backup**: The original file is backed up as `config.yaml.bak.<old_version>` before migration (only one backup per version is kept, existing backups are not overwritten).
- **Future Versions**: If the configuration file version is higher than what the program supports, the program only issues a warning and **continues to start without rewriting the file** (to prevent old programs from corrupting new format configurations).
- **Migration Failure**: **Terminates startup**, the original file remains untouched (since it was backed up before migration, it can be manually rolled back). Startup also terminates if the `version` field is missing or there is no migration path for the version.
- **Atomic Write**: Migration uses a temporary file + rename to persist to disk, avoiding partially written configuration files.

> ⚠️ In earlier versions, `enable_captcha` and `captcha_ttl` were under `yggdrasil.security.*`. After upgrading to v3, the `v2→v3` migration automatically moves them to the top-level `security.*`, so no manual intervention is required.

## Field Descriptions

### Top-level

| Field | Type | Description |
|-------|------|-------------|
| `version` | string | Configuration schema version (current `"3"`) |

### `site` — Site Information

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `site.name` | string | `"HRPAuth"` | Service name, appears in `GET /status` and Yggdrasil `meta.serverName` |
| `site.implementation` | string | `"HRPAuth"` | Implementation name |
| `site.version` | string | `"1.0.0"` | Implementation version |

### `server` — HTTP Service

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `server.port` | string | `":8080"` | Listening port (must include colon) |
| `server.cors_origin` | string | `"*"` | CORS allowed Origin, `"*"` means all |

### `callback` — Callback Address

| Field | Type | Description |
|-------|------|-------------|
| `callback.url` | string | Backend callback address (appears as `backend.url` in `GET /status`) |

### `frontend` — Frontend Address

| Field | Type | Description |
|-------|------|-------------|
| `frontend.url` | string | Frontend page address |

### `keygen` — Key Generation

| Field | Type | Description |
|-------|------|-------------|
| `keygen.enable` | int | Whether to enable the `POST /generate-key` endpoint (`0`/`1`) |

### `database` — MySQL

| Field | Type | Description |
|-------|------|-------------|
| `database.host` | string | Host address |
| `database.db_name` | string | Database name |
| `database.user` | string | Username |
| `database.password` | string | Password |
| `database.charset` | string | Character set, recommended `utf8mb4` |

### `verification_code` — Email Verification Code Storage

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `verification_code.code_ttl` | int | `600` | Verification code TTL (seconds) |
| `verification_code.storage_dir` | string | `"./cache/verification_codes"` | Directory for storing verification code JSON files |

### `redis` — Redis

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `redis.host` | string | `"localhost"` | Host |
| `redis.port` | int | `6379` | Port |
| `redis.password` | string | `""` | Password (leave empty for no password) |
| `redis.db` | int | `0` | Database number |
| `redis.prefix` | string | `"hrpauth_"` | Namespace prefix for all keys |

### `smtp` — Email

| Field | Type | Description |
|-------|------|-------------|
| `smtp.host` | string | SMTP server |
| `smtp.port` | int | SMTP port |
| `smtp.username` | string | SMTP username |
| `smtp.password` | string | SMTP password |
| `smtp.encryption` | string | `"tls"` / `"starttls"` / `"none"` |
| `smtp.from_email` | string | Sender email address |
| `smtp.from_name` | string | Sender display name |

### `security` — HRPAuth Business Layer (**Note: At top-level, not under yggdrasil**)

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `security.password_cost` | int | `10` | bcrypt cost. Larger values are more secure but slower |
| `security.rate_limit_max_attempts` | int | `10` | Max login failure count |
| `security.rate_limit_window_sec` | int | `600` | Login failure window (seconds) |
| `security.enable_captcha` | bool | `true` | **Enable graphical captcha** (mandatory validation for `/register`) |
| `security.captcha_ttl` | int | `300` | TTL for graphical captcha in Redis (seconds) |

> ⚠️ **Historical Migration Note**: In earlier versions, `enable_captcha` and `captcha_ttl` were under `yggdrasil.security.*`. **They have now been migrated to the top-level `security.*`**, and the old paths no longer take effect. When upgrading from an old version, the `v2→v3` chain migration will automatically complete this field migration, requiring no manual intervention.

### `manage` — Operations Manage Token (M-T)

| Field | Type | Description |
|-------|------|-------------|
| `manage.token` | string | **Manage Token (M-T)**, randomly generated by `utils.GenerateRandomToken(32)` on first startup and written to `config.yaml` |

**Purpose of M-T**: Acts as a "super remember token". For all site endpoints authenticated by Remember Token (`remember_token` / `remtoken` / `rt` fields), it is equivalent to the target user's `remember_token`, but the target user must be explicitly specified via `uid` or `email`.

Typical usage scenarios (examples):

```bash
# Query any user profile using M-T
curl -X POST https://auth.example.com/user \
  -H "Content-Type: application/json" \
  -d '{"remember_token":"<M-T>","uid":"42"}'

# Enable TOTP for any user using M-T
curl -X POST https://auth.example.com/totp/setup \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","remtoken":"<M-T>"}'

# Reset any username using M-T
curl -X POST https://auth.example.com/change-username \
  -H "Content-Type: application/json" \
  -d '{"remember_token":"<M-T>","uid":"42","username":"NewName"}'
```

> ⚠️ **Security Warning**: M-T is equivalent to a highest-privilege operator, **do not leak it**. To rotate M-T, edit the `manage.token` field in `config.yaml` and restart the service.

### `yggdrasil.server` — Yggdrasil Meta Information

| Field | Type | Description |
|-------|------|-------------|
| `yggdrasil.server.name` | string | Yggdrasil `meta.serverName` |
| `yggdrasil.server.implementation` | string | Yggdrasil `meta.implementationName` |
| `yggdrasil.server.version` | string | Yggdrasil `meta.implementationVersion` |
| `yggdrasil.server.signature_public_key_path` | string | Path to signature public key file |
| `yggdrasil.server.signature_private_key_path` | string | Path to signature private key file |
| `yggdrasil.server.textures_storage` | string | Directory for texture file storage |
| `yggdrasil.server.links.homepage` | string | Homepage link in metadata |
| `yggdrasil.server.links.register` | string | Registration page link in metadata |
| `yggdrasil.server.skin_domains` | array | List of allowed skin domains |

### `yggdrasil.security` — Yggdrasil Protocol Layer

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `yggdrasil.security.token_expiry_days` | int | `15` | accessToken TTL (days) |
| `yggdrasil.security.session_expiry_seconds` | int | `28800` | Refresh token/session TTL (seconds) |
| `yggdrasil.security.max_texture_width` | int | `1024` | Max texture width (px) |
| `yggdrasil.security.max_texture_height` | int | `1024` | Max texture height (px) |

### `yggdrasil.feature_flags` — Feature Switches

See [feature-flags.md](./feature-flags.md) for details.

## After Modifying Configuration

After modifying `config.yaml`, the **service must be restarted** to take effect (hot reloading is not implemented at runtime).
